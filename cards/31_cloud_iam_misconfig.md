# Cloud & IAM Misconfiguration (AWS / Azure / GCP)

*Keywords: cloud misconfiguration, IAM, S3 bucket public, overly permissive policy, IMDS 169.254.169.254, IMDSv1, assume role, privilege escalation cloud, GCP service account, Azure managed identity, storage account public, iam:PassRole, wildcard policy, scoutsuite prowler, cloud metadata credentials, public blob.*

## What cloud/IAM misconfig covers and where to look

Cloud findings are usually configuration, not code: publicly exposed storage, over-permissive IAM policies, and reachable metadata services that hand out credentials. The highest-yield targets: **object storage** (AWS S3, Azure Blob, GCS) left public or world-writable; **IAM policies** with wildcards (`Action:"*"`, `Resource:"*"`) or dangerous permissions that allow privilege escalation; **instance metadata** (IMDS) reachable via SSRF; and **exposed secrets** (keys in public repos, env files, CI logs). Stay strictly inside the authorized cloud account/subscription and the engagement's scope — enumerating another tenant's resources is out of bounds. Use read-only, least-touch checks: enumerate and prove access, don't create/destroy resources or move data at scale.

## Cloud detection — storage, metadata, and identity (impact-limited)

**Public storage** — test a bucket/container for anonymous list/read: `aws s3 ls s3://<name> --no-sign-request`, an unauthenticated HTTPS GET of a known blob, or `gsutil ls gs://<name>`. Anonymous **list** is a finding; read of one non-sensitive object proves it — don't download the whole bucket. World-**writable** is worse (integrity): prove by writing a single benign marker object (with permission) then deleting it. **Metadata/SSRF pivot** — if you have SSRF (see the SSRF card) to `http://169.254.169.254/latest/meta-data/iam/security-credentials/` (AWS IMDSv1), `http://169.254.169.254/metadata/instance?api-version=... ` with `Metadata:true` header (Azure), or `metadata.google.internal` with `Metadata-Flavor:Google` (GCP), the service may return temporary role credentials. Read **one** field to prove reach; do not harvest and use keys beyond confirming identity (`aws sts get-caller-identity`). **Exposed keys** — grep public repos/JS/env for `AKIA...`, and if found, validate scope with `get-caller-identity` only.

## IAM privilege-escalation paths

Given a set of credentials/permissions (from a finding, in scope), map escalation with read-only enumeration (`aws iam get-account-authorization-details`, ScoutSuite, Prowler, PMapper, CloudFox — all can run non-intrusively). Classic AWS escalation primitives to look for: `iam:CreatePolicyVersion` / `iam:SetDefaultPolicyVersion` (rewrite your own policy), `iam:PassRole` + `ec2:RunInstances`/`lambda:CreateFunction` (assume a more-privileged role), `iam:CreateAccessKey` on another user, `sts:AssumeRole` on an over-trusting role, `iam:UpdateAssumeRolePolicy`. Azure: over-scoped role assignments, `Contributor` where `Reader` suffices, managed-identity abuse. GCP: `iam.serviceAccounts.getAccessToken`/`actAs`, `setIamPolicy` on a project. **Prove the path exists** (enumeration shows the permission) rather than actually escalating and taking privileged actions on a live account — a documented reachable escalation is the finding.

## Cloud/IAM CVSS and remediation

Publicly readable storage exposing sensitive data: `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` = 7.5 (Critical if it's PII/secrets at volume); SSRF-to-IMDS credential theft or an IAM path to account-admin: `AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H` ≈ 9.9. Root cause: default-open or wildcard permissions and legacy metadata (IMDSv1) trust. Remediation: enforce least privilege (no `*` actions/resources; scope by tag/condition); block public access at the account level (S3 Block Public Access, storage-account "disallow public"); require **IMDSv2** (session-token, hop-limit 1) and restrict egress so SSRF can't reach metadata; rotate/scope keys, prefer short-lived role credentials over long-lived keys; enable logging (CloudTrail/Activity Log) and run ScoutSuite/Prowler in CI to catch drift.
